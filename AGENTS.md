- Start with a Python command-line backend prototype; do not introduce a website or JavaScript stack unless the user explicitly asks.
- For the first milestone, accept at least two item photos and one tag photo, either through explicit `--item`/`--tag` paths or an unordered top-level `--photo-folder` batch.
- Use OpenCV only for measurable image-quality checks such as resolution, blur, lighting, and possible glare. Use a pretrained vision model for garment understanding and tag extraction; do not plan custom model training for the first milestone.
- The selected first vision provider is the hosted OpenAI API using `gpt-5.6-luna`; do not substitute a local model, a different hosted model, or the `gpt-5.6` alias without explicit user approval. Use the Responses API, image inputs, strict Structured Outputs, low reasoning effort, and `store=False`.
- `pipeline_service.py` now connects the tested `openai_vision.py` provider boundary to `fact_validation.py` after successful local validation and OpenCV checks. It accepts ordinary Python paths, returns structured results, and never parses CLI arguments, prompts, prints, or exits; injected runners remain test-only boundaries. `classifier.py` is the thin terminal adapter that parses arguments, invokes the service, performs terminal review, prints one JSON result, maps exit codes, and saves approved CLI results. The ordinary runtime uses the real hosted Responses API; deterministic response fixtures, injected runners, and mocked SDK networking are permitted only in tests and are not a fake runtime provider.
- `api.py` is the localhost-only thin FastAPI adapter. It accepts individually uploaded JPEG, PNG, and WebP photos up to 10 MB under random names in ignored `local_uploads/`, and exposes typed operations for health, folder role detection/classification, fact validation, draft generation/validation, approval, exclusive local JSON saving, and explicitly approved CSV download. It delegates domain decisions to the service, validators, persistence, `photo_hosting.py`, and `depop_csv.py`; provider secrets must never reach browser code. Only Cloudinary listing-photo hosting is authorized cloud storage.
- Provider calls use a 60-second per-attempt timeout and at most two retries after the initial attempt, only for timeouts, rate limits, connection failures, and 5xx responses. Do not expose raw SDK exception text; return fixed secret-safe structured errors.
- `RESALE_OPENAI_SERVICE_TIER` is an explicitly authorized, backend-only speed option shared by photo-role detection, garment analysis, and pricing (including CLI calls). Default `auto` omits the tier to preserve project settings; `default` forces standard processing; `fast`/`priority` opt into premium Fast mode. Preserve the exact model, low reasoning, original image bytes/high detail, schemas, and validation. Record requested and actual tiers with existing latency metadata, reject invalid values before networking, and never silently retry on a different tier/model. Offline checks do not establish live speedup or quality; billed benchmarks still need explicit authorization.
- Successful provider calls record response/model identifiers, token usage, latency, and attempt count without calculating price.
- `photo_role_detection.py` is the unordered-folder provider stage. It uses neutral photo IDs, the same exact `gpt-5.6-luna`/Responses API/strict schema/low reasoning/`store=False`/bounded retry boundaries, predicts front/back/detail/tag roles, and selects one proposed tag from visual evidence. Folder mode now always continues with the deterministic best tag match; it records conservative confidence but never asks for tag confirmation. Folder mode makes two hosted requests; explicit role mode remains one request.
- `tests/test_live_smoke.py` is the only live OpenAI test path. It is skipped by default and requires `RESALE_RUN_LIVE_SMOKE=1`, `OPENAI_API_KEY`, at least two user-supplied item photos, and separate readable and unreadable tag photos. Enabling it authorizes two billed requests; never enable it without explicit user authorization. `tests/test_cloudinary_smoke.py` separately requires `RESALE_RUN_CLOUDINARY_SMOKE=1` and authorization: upload three synthetic images, verify public downloads, then delete only those test assets. It must never send user photos or call OpenAI/Depop.
- Read credentials only from `OPENAI_API_KEY`; never print, serialize, log, or commit the key.
- Keep image analysis, validated clothing facts, and listing-text generation as separate steps. Generate listing text only from validated facts.
- Generated descriptions contain only the generated title followed by `Size:` and validated inseam when present. Omit condition, style, age, and secondary-color prose; preserve those facts and their separate CSV fields. Never use `Labeled waist size`. This wording does not change canonical size values or CSV mapping, and does not rewrite existing approved descriptions or human edits.
- `listing_generation.py` deterministically generates editable title/description text only from final approved facts, revalidates them first, excludes Size from the title, includes Size and validated Inseam in the description, and omits blank optional fields. It does not call a model or export/publish.
- After fact approval, `classifier.py --review` must also allow terminal review and explicit approval of non-empty generated title/description text. Every approved result is automatically saved in `approved_listings/` with a random UUID JSON filename, using exclusive creation so no existing file is overwritten.
- Generated `approved_listings/*.json` files are local runtime data and must remain ignored by Git; track only `approved_listings/.gitkeep` unless the user explicitly requests a privacy-reviewed fixture.
- Treat `FIELD_CONTRACT.md` as the editable source of truth for listing-field priority, provenance, and deferred upload fields. Do not enforce unresolved fields in code until the user confirms their meaning or allowed values.
- Keep Depop destination mapping deterministic and separate from model output. Use the versioned vocabulary data, resolve Category before Size, and require review instead of fuzzy-guessing missing or ambiguous values.
- Brand mapping includes exact normalized aliases `Levi Strauss & Co.` and `Levi Strauss and Co.` to `Levi's (levi-s)` for the visible tag wording. Do not use substring/fuzzy brand matching or bypass tag provenance, confidence, or conflict validation.
- The strict provider schema enumerates controlled destination values (but not the large Brand vocabulary), limits each candidate field to its allowed sent photo roles, and requires JSON `null` for unknowns. Python repeats these provenance, placeholder, and exact-mapping checks as the final boundary.
- For resolved jeans categories, map tag labels such as `W36 L34`, `32x34`, and `Waist × Length 32 × 34 inch` by the exact waist value and retain the tag inseam as an internal validated fact for description generation. Instruct the hosted model to normalize visible pairs as `W{waist} L{length}` without dropping either measurement. Leave review-flagged Age candidates blank; retain exact, non-conflicting Style candidates even when low confidence.
